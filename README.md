# 施設ツアー（360度バーチャル見学）テンプレート

360度写真で施設の中を歩けて、場所ごとに解説が出るツアーです。保育園・クリニックなどの「行く前に中が分かる」ページを、写真と設定ファイルの差し替えだけで作れます。制作代行（自分たちが撮影して作り、納品する）を前提にしたテンプレートです。

- サーバー不要。HTML・CSS・JavaScript だけで動くので、GitHub Pages や施設のサーバーにそのまま置けます。
- 施設ごとにフォルダが 1 つ。フォルダを差し替えれば別の施設のツアーになります。
- 同梱の 2 施設（ひだまり保育園・みどりこどもクリニック）は**架空のサンプル**です。

## 見る人ができること

| 機能 | 内容 |
| --- | --- |
| ようこそ画面 | ロゴ・施設名・キャッチコピーと、「ガイドで見る」「自由に見る」の 2 つの入口 |
| 見回す | ドラッグ・スワイプ。慣性つき |
| 拡大・縮小 | ピンチ・ホイール・右側の＋−ボタン |
| 自動回転 | 右側のボタンでゆっくり回る。触ると止まる |
| 傾けて見回す | スマホを動かすと向きが変わる（スマホのみ。https で公開したときに使えます） |
| 全画面 | 対応している端末だけボタンが出る（iPhone の Safari は非対応のため出ません） |
| 歩く | 床の矢印を押すと、その方向へ歩くように切り替わる |
| 前後の部屋へ | 下の ‹ › で、決めた順番どおりに部屋を進む（廊下は歩いて移動） |
| 自動ガイド | 「園内をひとめぐり」「一日の流れ」など何本でも。決めた順に歩きながら字幕で案内。触ると一時停止、‹ › で前後へ |
| 読み上げ | ガイドの字幕を、端末の読み上げ機能で声にする（字幕のスピーカーのボタン。追加の料金なし） |
| 行き先の写真 | 矢印の名前と行き先ボタンに、行き先の小さな写真。PC では矢印にマウスを乗せると大きく出る |
| おすすめの矢印 | 次の部屋（ガイド中は次の案内の場所）へ向かう矢印を光らせ、「次は」と表示 |
| 解説ピン | 押すとその場所へ寄って、写真と説明が出る |
| お部屋の一覧・見取り図 | 写真つきの一覧と見取り図から、見たい場所へすぐ移動 |
| 問い合わせ | 見学予約・電話・地図・ホームページのボタン |
| はじめての方へ | 受付時間・お休み・持ち物・流れ（問い合わせと「その他」から開く） |
| その他 | この場所を共有、English／日本語、文字を大きく、ガイドをゆっくり、ライト／ダーク、このツアーについて |
| 電波がなくても見られる | サンプル（または `&demo=1`）のときだけ「その他」に出る。営業先で電波が弱くてもデモできる |

## 手元で動かす

写真を読み込む都合で、`index.html` をダブルクリックで開くと動きません。facility-tour フォルダの 1 つ上（例：デスクトップ）で次を実行し、ブラウザで <http://localhost:8000/> を開きます。

```bash
python -m http.server 8000 --directory facility-tour
```

同じ Wi‑Fi のスマホで見るときは `http://（PCのIPアドレス）:8000/` を開きます。ファイルを書き換えたあとに古い表示が残るときは、強制再読み込み（Ctrl＋Shift＋R）をしてください。

## URL で開き方を決める

| 書き方 | 意味 |
| --- | --- |
| `?f=hidamari` | 施設フォルダ `facilities/hidamari` を開く（省略すると施設の選択画面） |
| `&n=room0` | 最初の地点（tour.json の `id`）。指定するとようこそ画面は出ない |
| `&yaw=40` | 最初に向く方向（度） |
| `&guide=1` | すぐに自動ガイドを始める |
| `&intro=0` | ようこそ画面を出さない |
| `&embed=1` | 埋め込み用の詰めた表示（iframe の中では自動でこの表示） |
| `&theme=dark` | ライト／ダークを固定（`light` / `dark`） |
| `&lang=en` | 言語（施設が訳を用意しているときだけ。何も付けなければ端末の言語に合わせる） |
| `&src=poster` | どこから来たか（チラシ・ホームページなど）。計測に載る |
| `&demo=1` | 「電波がなくても見られるように保存」を出す |
| `&edit=1` | 編集モード（制作用。手元の PC の localhost でだけ開ける） |

## 施設のホームページに埋め込む

```html
<iframe src="https://（公開先）/?f=hidamari"
        style="width:100%;aspect-ratio:3/4;max-height:80vh;border:0;border-radius:16px"
        allow="fullscreen; gyroscope; accelerometer; web-share; clipboard-write" loading="lazy" title="ひだまり保育園 360度ツアー"></iframe>
```

WordPress は「カスタム HTML」ブロック、Wix・Jimdo・STUDIO などは「埋め込み／HTML」の部品に貼れます。

## LINE などで送ったときのプレビュー（施設ごとの入口ページ）

LINE や SNS にリンクを貼ったとき、施設名・説明・写真が出るように、施設ごとの入口ページを作ります。

```bash
python tools/make_pages.py https://（公開先の URL）/
```

`https://公開先/hidamari/` のように、施設フォルダと同じ名前の入口ページができます。保護者に送る・チラシの QR にするのは、この URL です。プレビューの画像は tour.json の `share`（地点と向き）から切り出します。tour.json や index.html を変えたら、もう一度実行します。サンプルの入口ページと QR は、公開先 `https://souuuu6.github.io/facility-tour/` で作ってあります。別の場所に置くときは、その URL で作り直してください。

検索エンジンに載せたくない施設は、tour.json に `"noindex": true` を入れてから実行します。

## チラシ・掲示物の QR

```bash
python tools/make_qr.py https://（公開先の URL）/
```

施設ごとに `qr.svg`・`qr.png`（QR だけ）と `poster.png`（A5 縦の案内。写真・施設名・QR）ができます。QR の行き先には `?src=poster` が付くので、計測で「チラシから来た人」を分けて数えられます。出どころを変えるときは 2 つ目に書きます（例：`python tools/make_qr.py https://… door`）。segno と Pillow が要ります（`pip install segno pillow`）。

## 英語で見せる（多言語）

1. 施設フォルダに `tour.en.json` を置き、tour.json に `"languages": ["en"]` を入れます。
2. `tour.en.json` には訳したい文だけを書きます（施設名・キャッチコピー・問い合わせの文字・はじめての方へ・ガイドの文・地点ごとの名前とピン）。書き方はサンプル 2 施設の `tour.en.json` をまねてください。ピンとガイドは tour.json と同じ順番です。
3. 画面のボタンなどの文字は `js/i18n.js` に入っています。ほかの言語を足すときは、そこに辞書を 1 つ足し、`tour.<言語>.json` を作ります。

見る人の端末が英語なら自動で英語になり、「その他」から日本語に戻せます。

## 電波がなくても見られるように保存（営業デモ用）

「その他 → 電波がなくても見られるように保存」を押すと、施設の一覧にあるツアーの写真や画面を、その端末に保存します（サンプル 2 施設で約 70 ファイル）。保存したあとは、電波がない・弱いときも保存した写しで動きます（つながるときは新しい中身を読みます）。https（または手元の localhost）で開いたときだけ使えます。営業に出る前に、使うスマホで一度押しておきます。

## 納品までの流れ（制作代行）

1. **ヒアリング**：見せたい部屋と順番、問い合わせ先（予約ページ・電話・地図）、ロゴ、色を聞く。
2. **撮影**：地点は 2〜3m おきに、カメラは毎回同じ高さ（目安 1.4m）。人の顔・名前・個人情報が写らないようにする。
3. **写真を整える**：`facilities/施設名/panos/` に入れ、横 4096px と下見用 1024px を作る。

   ```bash
   python tools/prepare_photos.py 元の写真のフォルダ facilities/施設名/panos
   ```

4. **編集モードで組み立てる**：`?f=施設名&edit=1` を PC で開く（次の節）。
5. **看板・問い合わせ・ガイドを入れる**：編集パネルの「施設の看板」「問い合わせボタン」「はじめての方へ」「自動ガイド」。訳が要るなら `tour.en.json` も作る。
6. **公開前チェック**：編集パネルの「公開前チェック」で、抜けや言葉づかいを確かめる。
7. **まとめて書き出す**：「納品用にまとめる（ZIP）」で、tour.json と写真・見取り図・ロゴを 1 つの ZIP にする。展開して `facilities/` に置けば完成。
8. **入口ページと QR を作る**：`python tools/make_pages.py https://公開先/` と `python tools/make_qr.py https://公開先/`。
9. **公開と埋め込み**：GitHub Pages などに置き、施設のホームページに iframe を貼る。

## 編集モードでツアーを作る

`http://localhost:8000/?f=施設名&edit=1` を開くと、右側に編集パネルが出ます（tour.json がまだなくても開けます）。

1. **写真を地点にする**：360度写真を画面にドラッグ＆ドロップ（または「360度写真を追加」）。1 枚が 1 地点。
2. **名前と順番**：「この地点」で名前と部屋名を入れる。部屋名のついた地点が「お部屋」の一覧に出る。「地点」の ↑↓ で順番を決める（一覧と ‹ › の順になる）。
3. **見取り図**：「施設」で見取り図の画像をえらび、各地点で「見取り図で位置を決める」→ 見取り図をクリック。
4. **向きを合わせる**：「見取り図の向き合わせ」のつまみで、見取り図の扇形を写真の向きにそろえる。移動したときの向きが自然につながる。
5. **矢印**：「矢印を置く」→ 床をクリック → 行き先をえらぶ。「戻る矢印も置く」で行き先にも戻りの矢印が付く。
6. **ピン**：「ピンを置く」→ 写真をクリック → タイトル・説明文・写真。
7. **直す**：「動かす・直す」でドラッグして動かす。押すと修正・削除。「見て試す」で実際に歩ける。
8. **ガイド**：「ガイドを増やす」で 1 本ずつ作り、名前（例：一日の流れ）とひとこと説明を入れる。案内したい地点で見せたい方向を向いて「今の地点・向きを案内に追加」→ 文を入れる。↑↓ で順番、「最初から試す」で確認。1 本もなければ部屋の順に自動で案内する。

作業中の内容はブラウザに下書きとして自動で残ります。最初からやり直すときは「下書きを捨てる」。

## 写真の差し替え方

同じファイル名で `panos/` に上書きすれば差し替わります（下見用の `_s.jpg` も作り直す）。編集モードで tour.json を書き出し直すと、tour.json の `rev`（版番号）が新しくなり、見る人の端末に古い写真が残らなくなります。部屋の向きが変わったときは、編集モードで矢印とピンの位置を直します。解説ピンの写真は `photos/` に入れます。360度写真の一部を切り出すなら次が使えます。

```bash
python tools/crop_view.py 360度写真.jpg 出力.jpg 向き 上下
```

## tour.json の形

```jsonc
{
  "name": "ひだまり保育園",            // 施設名
  "sample": true,                     // 「サンプル」表示（納品物では false か削除）
  "accent": "#e08a4f",                // テーマの色
  "logo": "logo.svg",                 // ロゴ（施設フォルダからの場所）
  "tagline": "0〜5歳の子どもたちが…",  // ようこそ画面のキャッチコピー
  "credit": "写真の説明など",          // 「このツアーについて」に出す（任意）
  "start": "entrance",                // 最初の地点
  "floorplan": { "image": "floorplan.svg", "width": 680, "height": 840 },
  "contact": {
    "reserve": { "label": "見学を予約する", "url": "https://…", "note": "平日 10:00〜16:00" },
    "tel": "03-1234-5678", "hours": "平日 9:00〜17:00",
    "map": "https://…", "address": "東京都…", "web": "https://…"
  },
  "analytics": { "ga4": "G-XXXXXXXXXX" },   // 任意
  "guides": [                               // 自動ガイド（任意・何本でも）
    { "id": "tour", "title": "園内をひとめぐり", "desc": "一覧に出るひとこと",
      "steps": [ { "node": "entrance", "look": [5, 0], "text": "ようこそ。玄関からご案内します。", "ms": 6000 } ] },
    { "id": "day", "title": "一日の流れ", "steps": [ … ] }
  ],
  "nodes": [
    {
      "id": "entrance", "name": "玄関", "room": "玄関",
      "image": "panos/entrance.jpg", "preview": "panos/entrance_s.jpg",
      "map": { "x": 328, "y": 720 },   // 見取り図の上の位置
      "heading": -115,                 // 写真の真ん中が、見取り図の上（北）から何度か
      "startYaw": 115,                 // この地点へ飛んできたときに向く方向
      "links": [ { "to": "hall1", "yaw": 115, "pitch": -26 } ],
      "pins":  [ { "yaw": 5, "pitch": 2, "title": "出入口", "text": "…", "image": "photos/entrance-door.jpg" } ]
    }
  ]
}
```

`yaw` は写真の中の左右の向き（真ん中が 0、右が＋、度）、`pitch` は上下（上が＋）です。編集モードを使えば手で書く必要はありません。

## 閲覧の計測

- `analytics.ga4` に Google アナリティクス 4 の測定 ID を入れると、次の操作が記録されます：ツアー開始、地点の表示、ピンを開く、ガイドの開始と最後まで見た、問い合わせボタン、共有。
- iframe で埋め込んだときは、埋め込み先のページにも同じ内容を `postMessage` で知らせます（`event.data.source === 'facility-tour'`）。施設側のサイトの計測にそのまま使えます。
- 計測を入れるときは、施設のプライバシーポリシーへの記載や、外部送信（電気通信事業法の外部送信規律）の公表が必要になる場合があります。施設の方と確認してください。

## 解説文を書くときの注意

病院・クリニックは医療広告ガイドラインの対象になり得ます。「地域No.1」「最高の」のような比較・最上級の表現、「必ず治る」のような言い切り、体験談の掲載は避けます。編集モードの「公開前チェック」は、こうした言葉を機械的に拾います（目安です。最終判断は施設の方と行います）。

## 読み込みの工夫

- 地点ごとに小さい下見画像（約 30〜80KB）を先に出し、高画質（約 0.2〜1.7MB）が届いたら差し替えます。
- 今いる地点の矢印の行き先を、裏で先に読み込んでおきます（同時に 2 本まで）。
- 写真は圧縮したままの形でためておき、表示する直前に画像に戻します（スマホのメモリを使いすぎないため）。
- 先読みは、隣の地点の下見画像と、次に行きそうな 1 地点の高画質だけにしています。データ節約モードの端末では先読みしません。
- 文字（Zen Maru Gothic）は、そのページで使う文字だけを読み込みます（全部だと約 900KB、絞ると約 150KB）。
- 通信が 20 秒止まったら打ち切って、もう一度押すよう案内します。

## 公開する（GitHub Pages）

1. このフォルダを GitHub のリポジトリにします。
2. リポジトリの Settings → Pages で、Branch を `main`・フォルダを `/ (root)` にして保存します。
3. 数分後に `https://（アカウント名）.github.io/（リポジトリ名）/?f=施設名` で開けます。

施設ごとに別のリポジトリにする場合は、`facilities/` にその施設のフォルダだけを入れます。

## 販売する前に差し替えるもの

- サンプルの写真（Poly Haven の CC0 素材と、プログラムで描いた部屋）は営業デモ用です。納品物では施設で撮影した写真に替えます。
- `sample` を外す、`contact` を本物にする、`credit` を書き換える（公開前チェックが残りを知らせます）。

## 素材について

- Poly Haven（CC0・表示義務なし）：small_empty_house、empty_play_room、yoga_room、kiara_interior、air_museum_playground、lebombo、st_fagans_interior、hospital_room_2、childrens_hospital
- ろうか・受付は `tools/render_rooms.py` でプログラムで描いた部屋です。

## セキュリティと個人情報

- サーバー・データベース・ログインはありません。ツアーの文章は文字として表示し、HTML として読み込むのは固定のアイコンだけです。
- `index.html` で、読み込んでよい先を決めています（自分のサイト・Google Fonts・Google アナリティクスだけ。Content-Security-Policy）。ほかの外部サービスを足すときは、ここに追記します。
- 編集モードは手元の PC（localhost）でだけ開けます。公開中のサイトで `?edit=1` を付けても、普通の表示になります。
- 埋め込み先への通知（postMessage）は、実際に埋め込んでいるページの住所あてにだけ送ります。tour.json の `analytics.embedOrigins`（例：`["https://example-hoikuen.jp"]`）を書くと、そのページに埋め込まれたときだけ送ります。
- 360 度カメラの元の写真には、撮影場所の位置情報（EXIF）が入っていることが多いです。`tools/prepare_photos.py` を通すと消えます。編集モードと公開前チェックは、撮影情報が残った写真を知らせます。
- 写り込み（子どもの顔・名札・作品・書類・暗証番号・車のナンバー）と、防犯の情報（鍵・防犯カメラ・裏口）は写さないか、ぼかします。
- GitHub Pages では、他人のサイトへの埋め込みを禁止する設定や、見る人を限定する設定はできません。限定したいときは、Cloudflare Access など鍵をかけられる置き場所に移します。
- GitHub のアカウントが乗っ取られると、ツアーを書き換えられます。2 段階認証を有効にしておきます。
